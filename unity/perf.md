# Gi performance in Unity

Generated by `unity/perf.sh`; the numbers live in `unity/perf-baseline.json`. Do not edit by hand.

## Method

- **Frames.** The `benchmarks/` frame harness (B1, C, W; the same scenarios, parameters, receipts and checksums) is compiled unchanged as `GiBenchmarks.dll` for netstandard2.1 (`unity/tests/Gi.Frames`; only `AggressiveOptimization`, two intrinsics probes and `Stopwatch.GetElapsedTime` are rewritten at build time). It runs inside the Unity test and on `dotnet`, on one core, one thread, 200,000 entities, 10 warm-up and 60 measured frames, p50 of the frame time; each dotnet row is the median of three process runs because the tiered JIT is bimodal on some frames (frame C ran at 22 ms in one process and 9 ms in the next). A run fails if the harness's receipts fail or the frame allocates.
- **dotnet rows** run the same harness pinned to one core. The net10 build is the vector build `src/Gi` ships for `net10.0`; Unity cannot reference it yet (`unity/ROADMAP.md`, Appendix B). The netstandard2.1 build is the scalar one Unity loads today.
- **ECS rows** use `GiEcsFixture`: emitters (static) plus probes with a value and gradient binding on the derived layer; wall time is `Tick` plus completing every job; Gi time is the sum of the five `Gi.*` profiler markers, summed across threads. They are not frame C.
- Backends: the editor runs CoreCLR (there is no Mono in Unity 7). Player columns are filled by the final verification pass (`unity/validate.sh`; the suite writes `GI_PERF_OUT`).
